## 1. システム構成

```
┌──────────── 自分のPC（Windows 11）────────────┐
│                                                │
│  ブラウザ (Chrome / Edge)                       │
│   └ 画面（React） ──HTTP(JSON)──┐               │
│                                ▼               │
│  Node.js サーバー   127.0.0.1:3000             │
│   ├ /api/*   … データの読み書き                │
│   └ /*       … 画面ファイルを配信              │
│                                │               │
│                                ▼               │
│  data/power.db (SQLite)   data/backups/*.db    │
└────────────────────────────────────────────────┘
```

| 方針 | 内容 |
|---|---|
| 形態 | ローカルWebアプリ。サーバー1つで画面とAPIの両方を配信する |
| 公開範囲 | 127.0.0.1 のみで待ち受け。同じWi-Fiの他の機器からも見えない。ログイン機能なし |
| 保存 | PC内の SQLite ファイル1つ（`data/power.db`） |
| 費用 | すべて無料のソフトウェア |

### 1.1 技術スタック

| 役割 | 採用 | 理由 |
|---|---|---|
| 実行環境 | Node.js 24（インストール済み v24.13.0） | — |
| 言語 | TypeScript | 画面・サーバー・計算を同じ型で共有できる |
| DB | SQLite（Node.js 組み込みの `node:sqlite`） | 追加インストール・ネイティブビルド不要で Windows でも確実に動く。高速 |
| サーバー | Fastify | 軽量・高速 |
| 入力チェック | Zod | 画面とサーバーで同じルールを共有 |
| 画面 | React 19 ＋ Vite ＋ React Router | ページ再読み込みなしで画面を切り替え、反応が速い |
| データ取得 | TanStack Query | 取得結果のキャッシュで画面切り替えを即時にする |
| グラフ | Chart.js ＋ react-chartjs-2 | 軽量、折れ線・棒・積み上げに対応 |
| 見た目 | 素の CSS（CSS変数） | 依存を増やさない。ライト/ダーク対応 |
| テスト | Vitest | 計算ロジック・APIの自動テスト |

## 3. 画面設計

### 3.1 画面一覧

| No | 画面 | URL | 内容 |
|---|---|---|---|
| ① | ホーム | `/` | 今日の摂取状況、最新の体重・体脂肪率、主要グラフ |

### 3.2 画面遷移

```
          ┌──────── メニュー（全画面から移動可）────────┐
          ▼        ▼        ▼        ▼         ▼        ▼
       ①ホーム  ②記録  ③グラフ  ④履歴  ⑤マイ食品  ⑥目標・設定
          │        ▲                 │
          └[今日の記録へ]┘   [行をクリック]→②（その日）
```

### 3.3 共通レイアウト

- PC：左に縦メニュー、右に内容。スマホ幅（〜640px）：下にタブバー。
- 保存はボタン1つ（Enter でも可）。保存後に「保存しました」と表示。削除は確認ダイアログを出す。
- 通信エラー時は画面上部にメッセージを出し、入力内容は消さない。

## 4. データ設計（論理）

```
 profile (1件)          goals ──(適用開始日で日付に対応)──┐
                                                          │
 body_logs (1日1件) ──── 日付 ────── meal_entries (1日n件) ┘
                                         │ food_id（任意）
                                         ▼
                                       foods
```

| エンティティ | 内容 | 主な項目 |
|---|---|---|
| profile | プロフィール（1件のみ） | 性別、生年月日、身長、基礎代謝、活動係数、減量ペース、たんぱく質係数、脂質% |
| body_logs | 体組成（1日1件） | 日付、体重、体脂肪率、メモ |
| meal_entries | 食事の1品 | 日付、区分、食品名、量メモ、食品ID、倍率、kcal、P、F、C、メモ |
| foods | マイ食品 | 名前、基準量、kcal、P、F、C、使用回数 |
| goals | 目標（履歴） | 適用開始日、kcal、P、F、C、目標体重、目標体脂肪率、目標期日 |

**設計方針**
- 食事は **記録した時点の値を保存** する（マイ食品を変えても過去は変わらない）。
- 除脂肪体重・体脂肪量・合計値・移動平均は **保存せず表示時に計算** する。
- ある日の目標は「適用開始日がその日以前で最も新しいもの」。
- 日付はローカル日付 `YYYY-MM-DD` で扱う。

## 5. 外部インターフェース（API 一覧）

画面とサーバーの間は `/api` 以下の JSON API でやり取りする。入出力の詳細は詳細設計書で定める。

| 区分 | API | 概要 |
|---|---|---|
| 体組成 | `GET/PUT/DELETE /api/body-logs…` | 期間取得、1日分の登録・上書き・削除 |
| 食事 | `GET/POST/PUT/DELETE /api/meals…` | 1日分取得（小計・合計つき）、1行の追加・更新・削除 |
| 食事 | `POST /api/meals/copy` | 過去日の食事をコピー |
| マイ食品 | `GET/POST/PUT/DELETE /api/foods…` | 検索・登録・更新・削除 |
| プロフィール | `GET/PUT /api/profile` | 取得・更新 |
| 目標 | `GET/POST/DELETE /api/goals…` | 履歴、ある日の目標、追加、削除 |
| 集計 | `GET /api/dashboard`, `/api/stats/daily`, `/api/stats/weekly` | ホーム用、グラフ用（日別）、週次サマリー |
| データ管理 | `GET /api/export`, `POST /api/import`, `GET/POST /api/backups` | 書き出し・復元・バックアップ |

## 6. 主要な計算仕様

| 計算 | 内容 |
|---|---|
| 除脂肪体重 | 体重 ×（1 − 体脂肪率/100）。体重と体脂肪率の両方がある日のみ |
| 体脂肪量 | 体重 × 体脂肪率/100。同上 |
| 体重の7日平均 | その日を含む直近7日の平均。記録が4日以上ある日のみ表示 |
| PFC→kcal | P×4 ＋ F×9 ＋ C×4 |
| 目安計算 | BMR（入力値優先、なければ Mifflin-St Jeor式）→ TDEE＝BMR×活動係数 → 目標＝TDEE×(1−減量%) → P＝体重×2.0g、F＝目標×20%÷9、C＝残り÷4 |

計算例（男性・30歳・175cm・75kg・活動1.55・−20%）：BMR 1,699 → TDEE 2,633 → **2,106kcal、P150g・F47g・C271g**

## 7. 非機能設計

| 区分 | 方針 |
|---|---|
| 性能 | 日付にインデックス。グラフ用データは一括取得し、期間切替は画面側で絞り込む。5年分のデータで各API 100ms 以内 |
| 信頼性 | DB は WAL モード。入力チェックを画面とサーバーの両方で実施。インポートは1トランザクションで失敗時は元に戻す |
| バックアップ | 起動時に1日1回 `data/backups/` へ自動コピー、30世代保持。インポート前にも自動バックアップ |
| セキュリティ | 127.0.0.1 のみで待ち受け。外部通信なし |
| 保守性 | 計算ロジックを1か所（shared）に集約し自動テスト。データ（`data/`）は Git 管理から除外 |
| 操作性 | キーボードだけで入力完結（Tab で移動、Enter で確定）。スマホ幅でも崩れない |

| 操作 | 方法 |
