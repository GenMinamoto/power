---

## 1. 目的・背景

- **筋肉量を増やしながら体脂肪を落とす（リコンプ／減量）** ために、日々の体重・体脂肪率・食事を記録し、推移を可視化する。
- スプレッドシートではなく、**ローカルPCで動くアプリ** として、入力しやすく、記録が確実に残る形にする。
- **費用は0円**（有料サービス・サブスク・クラウド利用なし）。インターネット公開もしない。

### 成功の判断基準
- 毎日の記録（体重・体脂肪率・食事）が1〜2分程度で入力できる。
- 「除脂肪体重（≒筋肉）が維持・増加し、体脂肪量が減っているか」がグラフで一目でわかる。
- PCを再起動してもデータが消えない。バックアップから復元できる。

## 2. スコープ

### 対象（MVP：最初に作るもの）
1. 体組成の記録（体重・体脂肪率）

3. よく食べる食品の登録（マイ食品）と、倍率入力による自動計算

## 3. 用語

| 用語 | 意味 |
|---|---|
| P / F / C | Protein（たんぱく質）/ Fat（脂質）/ Carbs（炭水化物）。単位は g |
| 除脂肪体重（LBM） | 体重 ×（1 − 体脂肪率）。筋肉量の目安として使う |
| 体脂肪量 | 体重 × 体脂肪率 |
| 食事区分 | 朝食 / 昼食 / 夕食 / その他（間食・サプリ・プロテイン等をすべて含む。細かく分けない） |
| 基礎代謝（BMR） | 安静時に消費するエネルギー（kcal/日） |
| TDEE | 1日の総消費カロリー ＝ 基礎代謝 × 活動係数 |
| マイ食品 | 自分で登録する食品マスタ（1食分あたりの kcal・PFC） |
| 倍率 | マイ食品の基準量に対して何倍食べたか（例：0.5、1.5） |

#### 4.4.1 目安計算の方法（一般的に最も使われている方法）

**入力項目**

| 項目 | 備考 |
|---|---|
| 性別 | 基礎代謝の式で必要 |
| 年齢・身長(cm)・体重(kg) | 体重は最新の記録を初期値にする |
| 基礎代謝(kcal) | 任意。体組成計などで測った値があれば入力。空欄なら式で計算 |
| 活動レベル | 下表から選択 |
| 減量ペース | ゆるやか（−10%）／標準（−20%）／維持（0%）から選択。初期値は「標準」 |

**計算の手順**

1. **基礎代謝（BMR）**：入力されていればその値を使う。空欄なら **Mifflin-St Jeor式**（現在もっとも広く使われ、精度が高いとされる式）で計算する。
   - 男性：10 × 体重(kg) ＋ 6.25 × 身長(cm) − 5 × 年齢 ＋ 5
   - 女性：10 × 体重(kg) ＋ 6.25 × 身長(cm) − 5 × 年齢 − 161
2. **1日の消費カロリー（TDEE）** ＝ BMR × 活動係数

   | 活動レベル | 係数 |
   |---|---|
   | ほぼ運動しない（デスクワーク中心） | 1.2 |
   | 軽い運動（週1〜3回） | 1.375 |
   | 中程度の運動（週3〜5回） | 1.55 |
   | 激しい運動（週6〜7回） | 1.725 |
   | 非常に激しい（肉体労働＋毎日のトレーニング） | 1.9 |

3. **目標カロリー** ＝ TDEE ×（1 − 減量ペース）。標準は TDEE の **約20%減**（TDEE − 500 kcal 前後と同程度）。筋肉を残すため、これより大きく減らすことは推奨しない旨を表示する。また BMR を下回る場合は警告を出す。
4. **PFCの配分**（筋肉を維持・増やしながらの減量で一般的な配分）
   - **P（たんぱく質）** ＝ 体重 × **2.0 g**（一般的な推奨範囲 1.6〜2.2 g/kg。係数は画面で変更可）
   - **F（脂質）** ＝ 目標カロリー × **20%** ÷ 9（画面で 20〜30% の範囲で変更可）
     - 出典：厚生労働省「日本人の食事摂取基準」脂質の目標量 20〜30%エネルギー／Helms ほか（2014）ナチュラルボディビルダー減量期の推奨 15〜30%
     - 20% とする理由：トレーニングのエネルギー源となる炭水化物を多く確保するため。ホルモンへの影響を避けるため 20% を下限とする
   - **C（炭水化物）** ＝（目標カロリー − P×4 − F×9）÷ 4（残りをすべて炭水化物にする）

**計算例**（男性・30歳・175cm・75kg・基礎代謝は空欄・中程度の運動・標準ペース）
- BMR ＝ 10×75 ＋ 6.25×175 − 5×30 ＋ 5 ＝ 1,699 kcal
- TDEE ＝ 1,699 × 1.55 ≒ 2,633 kcal
- 目標 ＝ 2,633 × 0.8 ≒ 2,106 kcal
- P ＝ 150 g（600 kcal）／F ＝ 2,106×0.20÷9 ≒ 47 g（421 kcal）／C ＝（2,106 − 600 − 421）÷ 4 ≒ 271 g

**補足表示**：減量ペースの目安は「体重の週0.5〜1%減」。2〜3週間の体重の7日平均の変化を見て、減りすぎ・減らなさすぎの場合は目標を見直すよう案内する。

### 4.5 ダッシュボード・グラフ

| ID | 要件 | 優先度 |
|---|---|---|
| D-01 | **今日の状況**：摂取 kcal / 目標、P・F・C の達成率（プログレスバー） | 必須 |
| D-02 | **体重の推移グラフ**（折れ線）＋ **7日移動平均線**（日々のブレを均す） | 必須 |
| D-03 | **体脂肪率の推移グラフ**（2週間に1回の測定点を結ぶ折れ線。測定が少ないため移動平均は使わない） | 必須 |
| D-04 | **除脂肪体重と体脂肪量の推移グラフ**（体脂肪率の測定日ごとの点を結ぶ。筋肉が残っているか確認するための最重要グラフ） | 必須 |
| D-05 | **摂取カロリーの推移**（日別の棒グラフ＋目標ライン） | 必須 |
| D-06 | **PFCの推移／バランス**（日別の積み上げ棒、または期間平均の比率） | 必須 |
| D-07 | 表示期間を切り替えられる（1週間 / 1か月 / 3か月 / 全期間） | 必須 |
| D-08 | 週ごとのサマリー（平均体重、平均体脂肪率、平均 kcal・PFC、前週比） | 推奨 |
| D-09 | 未入力日がわかる（カレンダー表示や記録の連続日数） | 任意 |

### 4.6 データ管理

| ID | 要件 | 優先度 |
|---|---|---|
| X-01 | データはPC内のファイルに保存し、アプリ・PCを再起動しても消えない | 必須 |

## 6. 非機能要件

| 区分 | 要件 |
|---|---|
| 費用 | 無料のソフトウェアのみを使用。有料API・クラウドは使わない |
| 動作環境 | Windows 11 のPC、ブラウザ（Chrome / Edge）で操作 |
| 公開範囲 | 自分のPC内のみ（localhost）。外部からアクセスさせない |
| 永続性 | データはPC内のファイル（例：SQLite データベース）に保存 |
| 起動のしやすさ | ダブルクリック1回（またはコマンド1行）で起動できる |
| 操作性 | 1日の入力が数分で終わる。キーボード中心でも入力できる。スマホ幅でも崩れない程度のレイアウト |
| 性能 | 数年分（食事記録 数万行）でも画面表示・グラフ描画が1秒程度 |
| 信頼性 | 入力ミスによるデータ破損を防ぐ（入力チェック、削除時の確認、バックアップ） |
| 保守性 | データとプログラムを分離。データファイルは Git 管理から除外（.gitignore） |
| 言語 | 画面表示は日本語 |

## 8. 技術方針（案）

費用0円・ローカル完結・記録が確実に残ること、**画面の動きが速いこと** を優先し、以下に決定する。

- **形態**：ローカルWebアプリ（自分のPCでサーバーを起動し、ブラウザで `http://localhost` を開く）
- **言語**：**Node.js（TypeScript）**。画面とサーバーを同じ言語で書け、画面の切り替えや入力の反応が速い構成にしやすいため、Python案より優先する。
- **画面**：React（Vite でビルド）。画面の切り替えはページを再読み込みせずに行う
- **グラフ**：Chart.js
- **保存**：SQLite（Node.js 組み込みの `node:sqlite`。1ファイルのデータベースで読み書きが速く、バックアップはファイルコピーで可能）
- ブラウザ内保存（localStorage / IndexedDB）のみの方式は、ブラウザのデータ消去で記録が消えるリスクがあるため採用しない。
